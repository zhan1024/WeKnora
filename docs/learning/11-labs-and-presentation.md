# 11 · 实操任务、验收与项目表达

## 1. 推荐实操顺序

每个任务都保留：改动文件、运行命令、测试证据、一个边界情况、两分钟口述。

### Lab 1：RRF 参数实验（入门）

- 在 mini 增加向量/关键词权重配置，而非直接改全局常量；
- 固定同一批语料与问题，比较 `0.7/0.3`、`0.3/0.7`；
- 覆盖双路命中、单路缺失、双路第一归一化。

**验收**：至少 3 条断言和一张结果表；能解释为什么 RRF 不直接比较 BM25 与 cosine 原始分。

### Lab 2：解析与分块鲁棒性（入门到中级）

- 构造含多级标题、未闭合代码块、超长段落的 Markdown；
- 验证面包屑、代码保护、偏移还原；
- 验证空文档失败，不停在 processing。

**验收**：正常/边界/失败各至少一例；能指出 mini 与主项目父子分块的差距。

### Lab 3：SSE 引用协议（中级）

- 把 `<ref id="c1"/>` 拆成 3～5 个流片段；
- 验证完整引用展开、普通 `<` 不受影响、未知别名删除；
- 验证 offset 重放不丢事件。

**验收**：能解释为什么需要 pending buffer 和 fail-closed，而不是简单字符串 replace。

### Lab 4：检索质量评估（中级）

- 准备 10～20 个问题和人工相关文档；
- 比较 vector-only、keyword-only、hybrid；
- 记录 Recall@K、MRR、响应耗时与重排成本。

**验收**：有固定问题集和结果表，不只展示一次“看起来回答正确”。

### Lab 5：只读 MCP 工具设计（中级到高级，不要求一次写完）

- 把 `hybrid_search` 包装成 `search_knowledge`；
- endpoint 带 Bearer token、工具 allowlist、KB scope；
- `tools/list` 与 `tools/call` 都校验；
- 写直接构造未授权工具调用的测试。

**验收**：能证明非授权 KB/工具不可访问，并说明限流、撤销和审计方案。

### Lab 6：长期记忆治理设计（设计题）

- 实现最小 `active/pending/superseded` 状态；
- 验证 pending 不进 Prompt，确认后生效；
- 模拟新旧偏好冲突与预算淘汰。

**验收**：不仅写 CRUD，还能解释隐私、冲突、预算和用户控制。

## 2. 两分钟项目表达模板

> 我在学习腾讯 WeKnora 时，没有停留在部署层面，而是把它的 RAG 主链路拆成文档解析、结构化分块、混合检索、RRF 融合、重排、引用生成和 SSE 流式输出，并用 Python + LangChain 做了一个可运行的 mini 对照项目。mini 支持多格式解析、真实 Embedding、DeepSeek 回答和前端流式展示。我重点复刻了加权 RRF 与跨流边界的引用解码，并用断言验证了单路退化、双路归一化和未知引用 fail-closed。主项目还包含多租户 RBAC、长期记忆和 MCP Server，我通过源码阅读和权限/工具调用场景整理了学习文档。下一步是补检索评估和持久化向量库，而不是直接宣称 mini 已具备完整企业级能力。

按真实完成情况删改，没做过的不要说“已经实现”。

## 3. 面试回答结构

```text
结论：先用一句话直接回答
机制：解释核心原理或数据流
实现：指出项目中的具体模块/设计
边界：说失败、性能、安全、成本或一致性
例子：给一次改动、测试或指标
替代：必要时给另一种方案和适用条件
```

### 示例：为什么用混合检索？

“结论是为了同时覆盖语义改写和精确术语。向量路处理同义表达，BM25 处理错误码、型号等字面匹配；WeKnora 用加权 RRF 按两路排名融合，避免原始分数量纲不同。mini 中我复刻了 0.7/0.3、k=60 和归一化。边界是 RRF 不保证所有语料都更优，需要用固定问题集评估 Recall@K、MRR 和重排成本。”

## 4. 常见扣分表达与修改

| 扣分表达 | 更好的说法 |
|---|---|
| “RAG 就是把文档向量化后问大模型” | 补充解析分块、混合召回、融合重排、上下文预算、引用和评估 |
| “RBAC 就是 admin 和 user” | 说明租户成员、四级角色、资源属主、KB scope、API Key 与数据过滤 |
| “记忆就是保存聊天记录” | 区分短期历史、长期记忆、确认/冲突/召回预算和事件流 |
| “MCP 就是 function calling” | 区分协议、工具发现/调用、传输、鉴权与 Client/Server 方向 |
| “SSE 每次 read 就是一个 JSON” | 说明 TCP  chunk 与 SSE 事件边界不同，需要缓冲与按空行解析 |
| “我的 mini 已完全复刻 WeKnora” | 明确已复刻算法与协议，完整产品能力仍有边界 |

## 5. 最终自测

- 不看代码，在 5 分钟内画出完整链路。
- 对任意一个模块说出：输入、输出、失败、性能、安全、测试。
- 对任意一次改动给出可复现验证，而不是“我试过可以”。
- 被追问不知道时，先限定已知边界，再说如何查源码/做实验，不编造。
