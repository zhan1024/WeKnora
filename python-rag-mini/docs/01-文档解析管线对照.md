# 01 · 文档解析管线对照

WeKnora 的文档入库链路:`knowledge_process.go` 编排 → docreader(独立 Python gRPC 服务)
解析 → `chunker` 结构化分块 → embedding → 向量索引。精简版用三个模块复刻其核心设计。

## 1. 统一产物:一切格式归一为 Markdown

| | WeKnora | 精简版 |
|---|---|---|
| 产物契约 | `ReadResult{MarkdownContent, ImageRefs, Metadata}`(proto) | `ParsedDocument(markdown, metadata)` |
| 有效性判定 | `document.is_valid()` ⇔ content != "" | `ParsedDocument.is_valid()`,完全相同 |
| 格式覆盖 | docx/doc/pdf/md/xlsx/pptx/epub/html/xmind/图片/URL… | md/txt/html/docx/pdf(展示机制即可) |

**为什么统一成 Markdown**:下游分块器只需理解一种结构(标题、表格、图片引用),
格式差异在解析层被抹平。这是整条管线最重要的架构决策。

## 2. 责任链组合器(docreader 的精华设计)

docreader 的 `chain_parser.py` 用两个组合器把所有解析器串起来,精简版逐行复刻:

```python
# FirstParser:按序尝试,第一个产出非空内容者胜,异常吞掉继续
# 对照: Docx2Parser = FirstParser.create(MarkitdownParser, DocxParser)
FirstParser(MarkitdownLike, FallbackParser)

# PipelineParser:上游输出作为下游输入,metadata 累积合并
# 对照: WebParser = PipelineParser.create(StdWebParser, MarkdownParser)
PipelineParser(HtmlToText, TextCleaner)
```

引擎按扩展名路由(`PARSER_REGISTRY`),对照 Go 侧 `engine_registry.go` 的
`ResolveParserEngine(fileType)` —— 知识库可以为不同文件类型配不同引擎。

## 3. 结构化分块(chunker)

| 机制 | WeKnora | 精简版 |
|---|---|---|
| 策略链 | `strategy.go`:heading → heuristic → recursive 逐层降级 + 校验器 | heading → recursive 两级 |
| 标题切分 | `heading_splitter.go` 按 #~###### 层级切段 | `_split_by_headings()` |
| 标题面包屑 | `header_tracker.go` 维护标题路径,存 `chunks.context_header` | `ParsedChunk.context_header`,如 `检索引擎 > 混合检索` |
| 代码块保护 | `fenced_code.go`:``` 围栏区间绝不切断 | `_find_protected_spans()` + 切点避开 |
| 原文偏移 | 每块记 `StartAt/EndAt`(rune 偏移),用于引用定位/高亮 | `start_at/end_at`(字符偏移) |
| 超长兜底 | `splitter.go` 递归切分 | `_recursive_cut()`:段落→句子→字符 |

**关键细节**:WeKnora 分块"宁超长不切断代码块"——切断的代码块对检索和展示都是灾难。
精简版 `_recursive_cut` 的切点若落在保护区间中间,会延长到区间结束。

## 4. 入库状态机(knowledge_process.go)

```
processing → completed
           ↘ failed(error_message 记录阶段与原因)
```

对照点:
- 分阶段记录:`beginStage(StageDocReader/StageChunking/StageEmbedding)`
- **任何阶段失败都不停留在 processing** —— WeKnora 踩过的坑:embedding 模型被删时
  文档不能永远"解析中",必须落 failed 并记录原因。精简版 `ingest_file` 的
  try/except 完整复刻了这一语义(`task.error_message = f"[{stage}] {e}"`)
- WeKnora 用 asynq 异步队列 + 后处理子任务(摘要/问题生成/图谱/Wiki),精简版
  同步执行、不含后处理 —— 这些是产品化增强,不影响理解主链路

## 5. 精简版没有复刻的(知道有即可)

- PDF 逐页扫描路由的图片面积主信号(需 pypdfium2)、VLM OCR、图片对象存储
- gRPC 服务边界(docreader 独立部署、ReadStream 图片逐帧流式传输)
- 父子分块(命中子块回捞父块)、MMR 多样性、FAQ 优先
