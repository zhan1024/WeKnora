# 05 · mini 面试问答与扩展练习

## 一、快速问答

### 1. 这个 mini 项目用了 LangChain 的什么？

**答**：主要复用 Embeddings/ChatOpenAI 接口与文本处理生态，混合检索、RRF、引用和流协议仍由项目自己实现。这说明框架提供组件，不会自动给出完整 RAG 产品策略。

### 2. 为什么向量检索使用内存全量计算？

**答**：教学语料小，全量 cosine 简单、确定、易调试。大规模数据应换 ANN 向量库，并保留统一检索返回契约，而不是让业务层直接依赖数组。

### 3. `match` 和 `candidate` 有何区别？

**答**：candidate 是每路初召回候选深度，match 是融合/重排后返回或进入上下文的数量。前者影响召回覆盖和成本，后者影响上下文精度与 token。

### 4. 为什么双路都排第一时融合分为 1？

**答**：代码除以理论最大 RRF，即 `(vW+kW)/(k+1)`，所以双路第一归一化为 1。仅向量第一则约为 0.7，仅关键词第一约为 0.3，三路路径输出范围因此一致。

### 5. 哈希 embedding 能用于生产吗？

**答**：不建议。它主要表达 token 哈希计数，不具备可靠语义泛化，只适合离线验证调用链。真实检索应使用经过自己语料评估的语义 embedding。

### 6. 为什么引用要服务端注册？

**答**：模型只能引用真实检索结果分配的别名，服务端展开时校验，未知别名删除，减少编造来源。还需要评估引用是否支持句子，不能只看格式合法。

### 7. `MemoryStreamManager` 是长期记忆吗？

**答**：不是，它是一次回答的 append-only 事件存储，用于实时推送和 offset 重放。长期记忆是跨会话的用户语义信息，需要另一套数据模型和治理。

### 8. 为什么需要 `chat.references` 独立事件？

**答**：来源元数据可以在正文生成前先发给前端，渲染引用卡片并提供上下文；增量正文则只负责文本。事件分离也便于重放和前端状态管理。

### 9. 为什么静态前端也要处理 XSS？

**答**：模型回答和文档内容都不可信，若直接注入 innerHTML，可能执行恶意标记。mini 先转义，再只生成固定的引用标签；生产富文本还需要严格 Markdown/HTML 消毒。

### 10. mini 能否直接部署到公网？

**答**：不建议。当前缺认证、租户、限流、持久化、多副本事件共享、完整上传治理和观测。它是本地学习项目，生产化必须逐项补齐并做安全评审。

## 二、扩展练习

### 练习 A：为 RRF 写正式测试

覆盖：

- 双路第一等于 1；
- 单向缺失只贡献一路；
- 多列表取最好名次；
- 仅关键词 BM25 归一化；
- 同分排序是否稳定/是否需 tie-breaker。

**验收**：命令可重复运行，断言不依赖远程模型。

### 练习 B：增加一个评估脚本

输入 JSONL：`question` + `relevant_sources`。分别跑 vector/keyword/hybrid，输出 Recall@1/3/5 和 MRR。

**验收**：至少 10 条问题，包含无答案和精确术语两类；结果可保存为表格。

### 练习 C：把内存向量换成 pgvector

保持 `vector_search(query_embedding, top_k)` 的输入输出不变，新增建表、写入、删除和重建索引。

**验收**：重启后数据仍在；维度不一致有明确错误；同一问题结果可与内存实现对照。

### 练习 D：实现最小 ReAct

使用 LangGraph 或手写循环，把 `hybrid_search` 作为唯一工具，限制最大 3 轮。工具结果回写消息，最终回答仍走引用注册。

**验收**：构造“需要检索”和“不需要检索”两例，记录每轮消息和停止原因。

### 练习 E：补一个只读 MCP endpoint

使用 MCP SDK 暴露 `search_knowledge`，带 Bearer token、KB scope 和 call 时二次鉴权。

**验收**：未授权工具直接 call 被拒绝；query string token 不被接受；撤销后旧 token 失效。

## 三、项目复盘的正确说法

“mini 复刻了解析/分块、混合检索、RRF、引用和 SSE 的关键机制，支持真实 embedding 与 DeepSeek，并有原生前端。我用具体断言和浏览器交互验证了核心链路。它目前是教学实现，持久化、权限、Agent、MCP 和长期记忆仍是后续扩展方向。”

不要把“计划扩展”说成“已经完成”，也不要只讲使用了哪些库而讲不出自己写的关键算法。
