# 02 · 流式协议对照

WeKnora 的问答输出不是"一次性返回",而是一条**可重放的 append-only 事件流**,
经 SSE 逐帧推给浏览器。这套设计支撑了两个产品能力:流式打字机效果、刷新页面不断线。

## 1. StreamManager:只有两个方法的接口

```go
// internal/stream/factory.go
AppendEvent(ctx, sessionID, messageID, StreamEvent)         // 生产者只追加
GetEvents(ctx, sessionID, messageID, fromOffset) (events, nextOffset, error)  // 消费者按 offset 拉
```

| | WeKnora | 精简版 |
|---|---|---|
| 单机实现 | `memory_manager.go`:进程内 map + RWMutex | `MemoryStreamManager`:dict + RLock |
| 多副本实现 | `redis_manager.go`:RPUSH + LRANGE,TTL 1 小时 | (不涉及,机制同构) |
| 竞态防护 | GetEvents 返回副本 | `get_events` 返回 `list(...)` 副本 |

**为什么接口只有追加和按偏移读取**:因为生成 goroutine 与 SSE 连接完全解耦。
生成只负责写事件;HTTP 层 100ms 轮询拉新事件推给客户端。连接断了?事件还在,
重连时从 offset 0 重放历史、再接着拉新的 —— 这就是 `continue-stream` 断线续传。

精简版演示:`main.py ask ... --stream` 结尾会从 offset 0 重放全部事件帧。

## 2. 事件类型

对照 `internal/event/event.go`,精简版保留了问答主链路的几个:

| 精简版 | WeKnora | 时机 |
|---|---|---|
| `chat.references` | (knowledge 引用事件) | 检索完成后、生成前下发,前端渲染角标 |
| `chat.start` | `EventChatStart` | LLM 开始生成 |
| `chat.stream` | `EventChatStream` | 每个增量片段 |
| `chat.complete` | `EventChatComplete` | 收尾,携带完整文本 |
| —(未复刻) | `agent.thought` / `tool_call` / `progress` ... | Agent 层的思考/工具事件 |

SSE 帧格式:`event: <type>\ndata: <json>\n\n`(`format_sse`)。

## 3. 引用流解码器:本模块最有意思的部分

**问题**:WeKnora 要求模型输出私有引用标签 `<ref id="cN"/>`(cN 是请求级来源别名)。
但 LLM 是逐 token 流式输出的,一个标签可能被拆到两个 chunk 边界两侧:

```
chunk 12:  "...加权融合<re"
chunk 13:  "f id=\"c2\"/>可以..."
```

直接把 chunk 12 推给客户端,用户会看到一个诡异的 `<re`。

**WeKnora 的解法**(`citations.go` 的 `citationStreamExpander`),精简版
`CitationStreamExpander` 逐行对照复刻:

1. 每来一个 chunk,先拼接 `pending + chunk`
2. 扫到 `<` 且疑似标签开头(`<ref`/`<kb`/`<web`)但还没有 `>` → 整段缓存进 pending,**不上线**
3. 凑齐完整标签 → 查别名注册表:已知别名展开为公开引用(`c1` → `[1]`),**未知别名 fail-closed 直接删除**(防止模型瞎编一个不存在的来源)
4. 普通 `<`(如"普通<符号>")原样放行

安全属性:**部分标签永远不会泄漏到客户端**;前端拿到的永远是要么完整展开、要么不存在的引用。

测试里专门验证了跨 3 个 chunk 拼装的 `<ref id="c2"/>` 和未知别名 `c9` 的删除,
你可以跑 `--stream` 观察离线模式故意按 6 字符切片时引用依然完整展开。

## 4. 私有标签 → 公开引用的两次渲染

| 阶段 | 形态 | 谁在做 |
|---|---|---|
| 模型输出 | `<ref id="c2"/>` | LLM(协议 prompt 约束) |
| 流解码后 | `[2]`(精简版)/ `<kb ...>` 公开标签(WeKnora) | expander |
| 前端展示 | 悬浮角标,可点击查看原文 | Vue 组件 |

为什么不让模型直接输出 `[2]`?因为 `[2]` 是普通文本,模型可能编造、编号可能越界,
而私有标签协议让**引用必须经过注册表校验**:别名是服务端分配的,模型只能引用
真实检索到的资料,编不出不存在的来源。这是 RAG 引用可信的关键设计。
